Perseus embedding test

Laws XI, Stephanus 918 — five URL variants, live-embedded.

What to look for. Any frame showing a browser error, a blank white box, or a “refused to connect” message means embedding is blocked for that variant. Any frame showing Greek or English text means it works. Compare how much Perseus navigation furniture each variant drags in — least furniture wins.

Also open your browser console (⌘⌥J in Chrome, ⌘⌥K in Firefox) and watch for X-Frame-Options or frame-ancestors errors — those are the definitive signal, since a GET can send headers a HEAD request did not.

1. Standard hopper page (baseline)

The URL you already have. Full page furniture expected.

https://www.perseus.tufts.edu/hopper/text?doc=Perseus%3Atext%3A1999.01.0166%3Abook%3D11%3Apage%3D918
If this renders the iframe route is viable. Note how much of the frame is actual text versus Perseus chrome.

2. Bare-text attempt — xmlchunk endpoint

Perseus exposes an XML chunk endpoint used internally by the hopper. If it returns just the passage, this is the ideal target.

https://www.perseus.tufts.edu/hopper/xmlchunk?doc=Perseus%3Atext%3A1999.01.0166%3Abook%3D11%3Apage%3D918
Best case. Raw text or XML with no navigation. If this works you can style it yourself.

3. Bare-text attempt — loadquery

Another internal hopper endpoint, sometimes returns a trimmed fragment.

https://www.perseus.tufts.edu/hopper/loadquery?doc=Perseus%3Atext%3A1999.01.0166%3Abook%3D11%3Apage%3D918
Speculative — may 404. A 404 here costs nothing.

4. English translation (Bury, Loeb)

Confirms the doc-ID pattern works for translations too — 1999.01.0166 is the Greek Laws; 1999.01.0165 should be the English.

https://www.perseus.tufts.edu/hopper/text?doc=Perseus%3Atext%3A1999.01.0165%3Abook%3D11%3Apage%3D918
If this shows English Laws 918, the Greek/English doc-ID pairing is predictable and worth capturing in the mapping table.

5. Scaife reader (modern viewer)

For comparison. Expected to be slower, and more likely to block embedding since it is modern infrastructure.

https://scaife.perseus.org/reader/urn:cts:greekLit:tlg0059.tlg034.perseus-grc2:11/
If this blocks but #1 renders, that settles hopper-over-Scaife on technical grounds as well as speed.
Aristotle Bekker check — the important one. Everything above is Plato, where Stephanus pages are well-behaved. The open question is whether the hopper accepts a Bekker page as a URL parameter for Aristotle. Try these by hand in a normal tab and see which lands on or near NE 1097b:
  1. …1999.01.0054:bekker page=1097b
  2. …1999.01.0054:book=1:chapter=7 — the chapter containing 1097b
  3. …alternate encoding of the space
If variant 1 works, Aristotle is as easy as Plato and the whole project is one evening. If only variant 2 works, Aristotle links land at chapter granularity — still useful, but worth knowing before you build the URL template.
